v1.0.0, <RELEASE DATE HERE>:

This release is now v1.0.0!

Everything has been completely rewritten from the ground up.

I am happy with the API and usage patterns now, so I no longer consider things as subject to change.

If you need the changelog notes from the older non-1.0 versions, you can find them in CHANGELOG_OLD.txt, but they will be removed from future releases at a later date.

* Builder is now a single header file (builder.h) instead of a standalone builder.exe.
	* There is no separate Builder executable to install or put on your PATH anymore.  All the core building functionality of Builder is now self-contained inside builder.h.
	* Your build script #includes "builder.h" (which can now be local to your project), #defines BUILDER_IMPLEMENTATION in exactly one translation unit, and calls Build() itself from its own main().
	* You compile and run that build script directly (e.g. clang -o build.exe build.c) and then run the compiled program instead of running a separate builder tool against it.
		* Because you now build this yourself, you can now configure the user config build yourself.
		* That compiled build.exe is now the program you use to build with.
			* It also means that program is easily small enough to live inside a GitHub project as it's really only ever going to be a couple hundred kilobytes big now.
			* GitHub's individual file limit in repositories is 100MB at the time of writing, so you'll be fine.
	* Therefore:
		* Builder's bundled Clang install is now removed.
			* You now MUST have a compiler already available (Clang, GCC, MSVC, or Clang-cl on Windows) for both (re-)compiling your build script and building your project.
		* BUILDER_DOING_USER_CONFIG_BUILD is now removed.
		* CommandLineArgs is now removed.
			* HasCommandLineArg() now takes (argc, argv) as the first parameters instead.
		* SetBuilderOptions( BuilderOptions *, CommandLineArgs * ) is now removed.
	* This is a breaking change.  Every previous concept of "run builder.exe against your build source file" no longer applies.
		* The build source file is no longer passed as a command line argument.
* The public API in builder.h is now plain C instead of C++.
	* Initializer lists were comfy, but the STL is dog-slow (shocker), bloats the size of a binary, and requiring it alienates C programmers.
	* C++ programmers can still use the C API no problem.
	* Every std::vector<std::string> field is now a StringList.
		* Use MakeStringList(...) to fill them, or the Add*( config, ... ) macros: AddSourceFiles, AddDefines, AddIncludes, AddCompilerArguments, AddLibPaths, AddLibs, AddWarningLevels, AddIgnoreWarnings, AddLinkerArguments.
	* Every std::string field is now a const char *.
		* Builder stores the pointer, it does not copy the string.
	* BuildConfig::dependsOn is now a ConfigPtrList of BuildConfig pointers instead of copies.
		* Use MakeDependencies(...) or AddDependencies( config, ... ) to fill it.
* AddBuildConfig() and AddBuildConfigUnique() are now removed.
	* Use CreateBuildConfig( BuilderOptions * ) instead, which returns a BuildConfig * for you to fill out.
	* Then call Build( BuilderOptions *, int argc, char **argv ) from your main().
* BuildConfig::name is now required, even if you only have one config.
* OptimizationLevel is now Optimization, and BuildConfig::optimizationLevel is now BuildConfig::optimization.
	* OPTIMIZATION_LEVEL_O0 is now OPTIMIZATION_DISABLED.
	* OPTIMIZATION_LEVEL_O1 is now OPTIMIZATION_PROGRAM_SIZE (which is now -Os on Clang/GCC).
	* OPTIMIZATION_LEVEL_O2 is now OPTIMIZATION_PROGRAM_BALANCED.
	* OPTIMIZATION_LEVEL_O3 is now OPTIMIZATION_PROGRAM_SPEED.
	* The default is now OPTIMIZATION_NONE, which passes no optimization flag to the compiler at all (previously -O0 or /Od).
* BuilderOptions::linkAgainstWindowsDynamicRuntime is now BuildConfig::useDynamicRuntimeOnWindows, so it can be set per config.
	* Builder also enables this automatically if a config has _DLL in its defines.
* Removed BuildConfig::noDefaultLibs.
* Removed BuildConfig::removeFileExtension.
	* As far as I could tell, no-one was using this one.  Let me know if I was wrong and I'll reimplement it.
* Removed GetCommandLineArgValue().
* Removed BUILDER_CALLBACK and the global OnPreBuild() and OnPostBuild() callbacks.
	* You now control your own main(), so just run your code before and/or after calling Build().
* Added BuilderOptions::selfRebuildConfig.
	* This is a BuildConfig * (created via CreateBuildConfig()) that you can use to tell Builder how to rebuild your build source file when it's changed.
	* This means you only ever need the raw compiler invocation once, when first ever building your build source file.
* Removed --nuke as a command line option.
	* Users typically clean their binaries manually via their file explorer, and if they need command line functionality then the OS already provides this.
	* The only time they're "deleting" binary files from within their editor is if they're "rebuilding", which we already have a dedicated mechanism for.
* Removed --visual-studio-build as a command line option.
* Builder now sets the working directory to the folder containing the build executable.
	* All relative paths in your BuildConfigs and generator options are now relative to the build executable instead of the build source file.
* If BuilderOptions::compilerPath is not set, Builder now uses "clang" from your PATH.
* Linux:
	* -lstdc++ is no longer added automatically.  Use clang++ or add -lstdc++ to BuildConfig::additionalLinkerArguments yourself.
	* Library names in BuildConfig::additionalLibs without a path or extension are now linked as -l:<name>.so.
* BuildConfig::OnPreBuild now runs before source files are globbed, so any source files it generates get picked up.
* BuildConfig::OnPostBuild now also runs when a build is skipped.
* Added support for clang-cl.
	* I don't know why people are using this, but they are, so there you go (don't say I never get you anything).
* BuildConfig::intermediateFolder is now BuilderOptions::intermediateFolder.
	* It is now relative to the build executable and defaults to "intermediate".
* Intermediate files are now named <source file name>_<hash>.o, where the hash is made from the compile command, the compiler version, and the source file path.
	* This means two source files with the same name in different folders (e.g. "src/render/util.c" and "src/audio/util.c") no longer overwrite each other's object file.
	* Changing a config's compiler arguments or upgrading your compiler now only rebuilds the affected object files.
* VS Code JSON generation is now in builder_vs_code.h.
	* BuilderOptions::generateVSCodeJSONFiles and BuilderOptions::vsCodeJSONOptions are now removed.
	* You must now manually invoke generation yourself by calling Builder_GenerateVSCodeJSONFiles( BuilderOptions *, VSCodeJSONOptions *, int argc, char **argv ).
	* #define BUILDER_VS_CODE_IMPLEMENTATION before including builder_vs_code.h.
	* VSCodeJSONOptions::builderPath is now VSCodeJSONOptions::buildCommand, and defaults to your build executable.
	* Every std::vector field is now a pointer plus a matching *Count field (e.g. taskConfigs and taskConfigsCount).
* Zed JSON generation is now in builder_zed.h.
	* BuilderOptions::generateZedJSONFiles and BuilderOptions::zedJSONOptions are now removed.
	* You must now manually invoke generation yourself by calling Builder_GenerateZedJSONFiles( BuilderOptions *, ZedJSONOptions *, int argc, char **argv ).
	* #define BUILDER_ZED_IMPLEMENTATION before including builder_zed.h.
	* ZedJSONOptions::builderPath is now ZedJSONOptions::buildCommand, and defaults to your build executable.
	* Every std::vector field is now a pointer plus a matching *Count field (e.g. taskConfigs and taskConfigsCount).
* Compilation database generation is now in builder_compilation_database.h.
	* BuilderOptions::generateCompilationDatabase is now removed.
	* You must now manually invoke generation yourself by calling Builder_GenerateCompilationDatabase( BuilderOptions *, CompilationDatabaseOptions *, int argc, char **argv ).
	* #define BUILDER_COMPILATION_DATABASE_IMPLEMENTATION before including builder_compilation_database.h.
	* The compilation database is now generated without compiling anything.
	* Each entry now uses a single "command" string instead of an "arguments" array.
* Visual Studio Solution generation is now in builder_visual_studio.h.
	* BuilderOptions::generateSolution and BuilderOptions::solution are now removed.
	* You must now manually invoke generation yourself by calling Builder_GenerateVisualStudioSolution( BuilderOptions *, VisualStudioSolution *, int argc, char **argv ).
	* #define BUILDER_VISUAL_STUDIO_IMPLEMENTATION before including builder_visual_studio.h.
	* VisualStudioConfig::options is now VisualStudioConfig::config, and is now a BuildConfig *.
	* Every std::vector field is now a pointer plus a matching *Count field (e.g. projects and projectsCount).
	* Generated projects no longer have a clean command, since --nuke is removed.  So cleaning Builder projects now don't do anything.
